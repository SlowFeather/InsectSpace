# 蛊虫组合与流派

当前完成 Unity 6 客户端与 .NET 本地服务器的凡蛊目录、所有权、六槽组合、流派判定和真实 TCP 通讯。MySQL/Redis 暂不接入，进程重启会丢失角色、背包、组合和操作回执。

## 启动

```powershell
./tools/Run-LocalServer.ps1 -LocalEconomy -EconomyConsole
# Unity 停止 Play 后，在另一个终端运行：
./tools/Start-GuPathDemo.ps1
```

客户端场景为 `Assets/InsectSpace/Demos/LocalGuPath.unity`。先请求服务器开窍，再刷新资料，即可使用一转蛊虫。左侧按名称、转数、主/支援流派筛选，点名称查看出处，点加入/移除编辑草稿，点击提交组合等待权威确认。支持空组合、恢复服务器组合、断线重连及未确认操作重试。

本地服务器明确赠予目录中的 43 种凡蛊作为开发背包；这是 LOCAL 数据，不是线上新角色赠送规则。高转蛊虫虽已拥有，仍受角色转数门槛限制。服务器控制台 `cultivation-xp` 发放模拟经验，`cultivation-proof` 在适用境界提供模拟突破凭据；客户端按既有转数流程逐阶突破，刷新后可使用更高转蛊虫。普通角色创建不会自动升级。

## 资料与配置

- 首批 43 条一至五转蛊虫记录（同名不同转数分开），配置 42 个流派 ID；没有相应凡蛊的流派目前仅可识别名称。
- [来源索引](Gu-Catalog-Sources.md) 记录每条转数/功能的原文章节与行号，区分明确设定和按效果设计的归类。资料存在冲突的冰刃蛊暂不收录，不含六转及以上仙蛊。
- 唯一配置源：`design/luban/GuPaths/Defines/gu.xml` 和 `Tables/*.json`。运行 `tools/Build-GuTables.ps1`，用固定 Luban 4.5.0 同步生成客户端/服务端代码和 bytes；不要手改 Generated。
- 生成目录为 Player/GuPaths/Generated 与 server/Generated/GuPaths，独立 GuTables 管理器。两份表按固定顺序、带长度前缀计算 SHA-256，任何目录差异都不能继续写入组合。
- 主标签表示本项目归属；支援标签只表示跨流派搭配贡献。标签不等同于原作道痕。虚道保留独立筛选 ID 并注明律道分支；飞行技巧、未开创/有争议的流派不自动加入。

## v1 判定规则

每只蛊虫向主流派贡献 3 分，向可选支援流派贡献 2 分。转数不增加分类分数，避免高转单蛊掩盖整套搭配。最多六槽；同一个进阶系列最多一只，不能靠重复装备或一到五转同系列叠加刷分。

所有得分按分数降序、流派 ID 升序返回，重排槽位不改变结果。最高分唯一且占总分至少 60%，才确定主流派；并且该流派有至少两只不同系列的蛊虫参与、覆盖至少两种功能定位，判为“已成型”。只有单一功能或单蛊时为“倾向”。并列第一或没有达到 60% 时为“混修”，不暗选较小 ID 为主流派。空槽组为“尚未配置”。

|组合示例|判定|
|---|---|
|一转月光蛊 + 一转小光蛊|月道成型：月道 5，光道 3，覆盖攻击/辅助|
|一转白豕蛊 + 一转黑豕蛊|力道倾向：只有辅助定位|
|一转月光蛊 + 一转骨枪蛊|混修：月道 3，骨道 3|
|三转全力以赴蛊 + 三转自力更生蛊|力道成型：攻击/治疗|
|三转驭狼蛊 + 三转狼魂蛊 + 四转狼嚎蛊|奴道成型：奴道 8，魂道 3，音道 2|

攻击、防御、治疗、移动、辅助、控制是项目定位标签。当前成型只产生可解释的流派资料，**不会自动生成杀招、增加伤害、升阶、增加道痕或获得大师/宗师境界**。参考功效文本不是已经实现的技能。后续技能与战斗系统可消费已确认组合，但需要另外定义效果、消耗和确定性帧命令。

## 权威与通讯

独立二进制协议 2004/v1，经现有本地 TCP 主机多路分发；经济/战斗资源/转数 2001–2003 保持原格式。请求只包含命令、请求 ID、操作 ID、预期修订、规则版本、目录哈希和最多六个蛊虫定义 ID，没有玩家身份、奖励、目标转数或客户端指定流派。

服务器使用已绑定身份和修炼快照校验：合法目录、所有权、转数、同系列重复、版本、修订及战斗状态；整个组合原子替换。战斗期间拒绝变更，失败不动原组合。服务接口只接收主机提供的修为与战斗上下文，本地主机在同一宿主线程协调处理；正式多进程部署仍需事务/租约。

只读快照返回玩家/归属区、背包、排序后的组合、当前修为及其修订、组合修订、服务器评分和功能覆盖。客户端绑定身份、关联请求、拒绝旧修订与不一致评分。草稿预览不覆盖已确认数据。写操作超时/掉线保留原操作 ID、修订和槽位；重试不会重复装备，原失败也会稳定重放。达到 4096 操作/奖励回执上限拒绝新增，不逐出旧记录而丢失幂等保证。

背包当前是每种定义至多一只的最小模型；没有蛊虫实例耐久、交易、消耗品扣除、炼化/合炼、掉落关卡或持久化。可信 `GrantOwned` 可供后续奖励服务调用，无远程发放指令。LOCAL 固定角色/loopback 连接不替代正式账号鉴权，也不提供在线失败后的本地回退。
