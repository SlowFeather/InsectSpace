# ADR 0005：养炼业务的实例库存与原子结算

状态：设计中；业务参数待用户确认。2026-10-03。生产接入仍需平台/服务端评审。

## 问题

2004/v1 的背包按定义去重，不能表示两只小光蛊参与同一蛊方，也无法指定毁掉哪一只。养炼不能把扣款、材料消耗、随机结果与装备更新拆成独立客户端请求。

## 实施边界

养炼在 Player/GuWorkshop 业务目录中实现无 Unity 依赖的契约及 2005/v1 协议；服务器 Compile Link 同份契约。保留 2001–2004 的二进制格式，不修改 shared、vendor、平台 Runtime/Editor 或 SDK。

蛊虫定义继续取自已有 Luban 来源目录。实例记录独立 ID、定义 ID、是否炼化和喂养有效期。商店、食料、单炼参数和合炼配方使用独立 Luban 表，并绑定现有目录指纹。服务器绑定身份，客户端只提交动作、实例/商品/配方标识、修订和操作号，不提交价格、概率或结果。

同一内存事务锁内检查钱包、库存、修为、战斗状态、配方与有效期，再结算费用、材料、成功/失败结果及实例增删。操作回执保存原请求和首次结果；重试不重新抽取，不重复支付。达到库存或回执容量时拒绝，不能逐出旧回执后重复处理。

饥饿采用服务器时间源，在养炼业务中计算；不进入确定性战斗模拟。客户端只显示服务器快照，断线时停止提交操作，重连恢复权威数据。进程重启清空是用户明确选择的本阶段边界。

现有 43 蛊赠送演示与新商店玩法必须明确区分。新流程不可从旧演示的装备或所有权入口绕过炼化、饥饿、购买和毁蛊规则。

## 验证计划

覆盖同种多实例、余额不足不改库存、食料匹配、饥饿/恢复边界、未炼化/休眠不可装备、合炼输入数量与唯一实例、成功与各失败分支、重复/并发请求不重扣不重抽、旧目录/修订拒绝、战斗期间锁定、畸形包以及真实 Unity/TCP 重连。执行 Foundation、Architecture、Unity 相关测试并记录真实结果。

## 回滚与兼容

当前仅 LOCAL 内存业务，不迁移生产存档。关闭新业务入口可继续原演示；旧客户端不自动进入新的实例库存。正式账号、持久化、移动平台网络和发布门禁不由此协议替代。
