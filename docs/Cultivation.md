# 转数、开窍与随机资质

日期：2026-10-02。交付范围：Unity 6 客户端、独立 .NET 服务端、共享纯 C# 模型和真实 TCP 协议。沿用本地内存阶段，不接 MySQL/Redis。没有把服务器控制台的演示经验、试炼凭据当作已完成的任务或灾劫玩法。

## 一次随机资质

沿用 [新手引导第 5 节](../design/narrative/Chapter01-Section01-Onboarding.md) 的项目初测方案；**概率、整数边界及玩家最低丁等是游戏改编，不是参考文章给出的抽取概率**。

| 资质 | 概率/万分权重 | 停止步数（含端点） | 初始元海占比（含端点） |
| --- | --- | --- | --- |
| 丁 | 20% / 2000 | 10–19 | 20–39% |
| 丙 | 50% / 5000 | 20–29 | 40–59% |
| 乙 | 25% / 2500 | 30–39 | 60–79% |
| 甲 | 5% / 500 | 40–49 | 80–99% |

服务器先抽档位，再分别均匀抽取档内步数和占比；不按步数线性换算元海。普通池没有开窍失败或十绝体。模型保留 `Extreme`（100%、50 步）供未来可信特殊角色使用，当前没有客户端指定资质接口。

抽样只在服务器开窍事务锁内进行，使用服务端密码学随机数；客户端不能传种子、概率、资质结果或步数。随机源不进入权威战斗模拟。记录按 `PlayerId + HomeRealmId` 识别；同一进程中重复创建、并发开窍、重连和重复操作均不重抽。**服务重启会丢失内存记录**；正式账号/角色槽、跨重启保存和删号重建防重抽账本尚未接入。

资质不加经验或货币奖励倍率，不永久限制转数；丁等到九转已有回归。元海占比是先天容量信息，不是当前剩余真元，也不等于仙窍品级。免费改善资质、花海行走演出和服务器路线校验仍待后续玩法接入，此面板不代表完整新手仪式。

## 权威突破

客户端只请求“下一境界”；服务端校验规则版本、幂等号、资料版本、战斗状态、经验和证明。成功只推进一步，消耗本阶段经验；失败不扣经验、不改资质或钱包。重复操作返回原结果与当前快照。

| 当前阶段 | 经验之外的门槛 |
| --- | --- |
| 一至五转初/中/高阶 | 无额外凭据，依次进一小阶 |
| 一至四转巅峰 | 当前转数的突破试炼凭据 |
| 五转巅峰 | 已验证完成的升仙凭据 |
| 六转 | 3 次已验证天劫，仙窍本源正常 |
| 七转 | 3 次已验证浩劫，仙窍本源正常 |
| 八转 | 3 次已验证万劫、至少 300000 主修道痕、无上大宗师、天道封锁已突破、本源正常 |
| 九转 | 拒绝继续升转，没有十转经验条 |

`GrantExperience`、`RecordEvidence` 是服务器内部可信入口，实际任务/挑战验证服务以后调用，客户端无这些操作码。事件号全局去重，证明绑定对应转数/小阶；跨角色复用事件号及旧阶段事件拒绝。三气操作、真实灾劫、升仙机缘概率和保底挑战**尚未制作**；升仙凭据表示可信外部流程已经完成。

规则 v1 的**本地演示经验**：凡人每步 `100 × 转数 × 小阶序号`（1/2/3/4），六至八转每步 `1000 × 转数`。这些不是正式平衡值，未来应进入版本化配置。开窍前服务器奖励可先积累经验，开窍后继续使用；资质与充值不改变门槛。

### 与经济、战斗的关系

成长复用同一连接的角色身份，使用独立快照版本和协议号。此次同步能量**类型**与资质容量元数据，不改钱包、储备或旧经济实验室的固定 100 点能量池；真元/仙元余额、恢复、跨转数战斗换算与正式技能数值需另行接入。不会把元海百分比误写成当前能量，或把仙元等同仙元石。

本地主机同一线程处理业务；KCP 房间活动时拒绝开窍、突破，撤离后恢复。旧经济面板默认不请求成长数据，修炼面板显式启用成长订阅，保留经济联调协议的兼容性。

## 模型、协议和目录

客户端业务目录：`Assets/InsectSpace/HotUpdate/Modules/Player/Cultivation/`。

- `Protocol/CultivationContracts.cs`：不可变资质/角色快照、枚举、规则、名称与门槛。
- `Protocol/CultivationPacket.cs`：二进制 codec 和本地 2001/2002/2003 分发器。
- `CultivationClient.cs`：身份/响应/版本校验、权威读模型、未知结果原操作号重试。
- `LocalCultivationPanel.cs`：独立 Unity 修炼名册面板。
- `server/InsectSpace.Server/Cultivation/CultivationService.cs`：内存记录、开窍事务、可信经验/证明、突破与去重。

服务器 Compile Link 同一份纯 C# 协议，不引用 Unity 或热更 DLL。没有修改 `shared`、`vendor`、平台 Runtime/Editor、asmdef。兼容与提取边界见 [ADR-0003](ADR-0003-Cultivation-Protocol.md)。

GF TCP 提供外层分帧。内部小端头为 `Int32 WireVersion=1`、`Int32 PacketId=2003`、`Byte Kind`（1 请求、2 响应）。上限 1024 字节；ID 最多 96 字节，限 ASCII 字母/数字/`-_.`。未知版本、未知命令、截断、非法状态和多余尾部字节均拒绝。

请求字段：`Command:byte`、`RequestId:int64`、`OperationId:text`、`ExpectedRevision:int64`、`RulesVersion:int32`。只有 Snapshot=1、Awaken=2、Breakthrough=3；没有目标转数、资质、经验、种子或证明载荷，身份由服务器连接上下文绑定。

响应含请求号、操作号、结果码、重复标记与完整快照。快照字段为 PlayerId、HomeRealmId、Revision、RulesVersion、Rank、Stage、Aptitude（Grade/SeaPercent/StopStep）、Experience、MainPathDaoMarks、三类灾劫计数、Proofs。服务器和客户端使用同一数据类型验证，不通过中文字符串猜转数。

内存角色、可信事件和每角色操作各有 4096 上限；整数溢出与容量满明确拒绝，不移除旧记录来允许重复入账。客户端不预升阶，断线清除可操作快照；未知结果保留原操作号重试，明确版本冲突后核对最新状态再提交新操作。

## 本地运行

```powershell
# 终端一：TCP 默认 7779，复用本地玩家主机
./tools/Run-LocalServer.ps1 -LocalEconomy -EconomyConsole
# 终端二：Unity 6 已打开、保存场景并停止 Play
./tools/Start-CultivationDemo.ps1
```

场景 `Assets/InsectSpace/Demos/LocalCultivation.unity` 通过 UnityCLI 原生 Editor API 创建。开窍后显示转数、资质、元海与步数；开窍按钮禁用，绕过 UI 重复请求也不会重抽。服务器控制台辅助命令如下，操作后在客户端刷新再突破：

| 命令 | LOCAL / SIMULATED 行为 |
| --- | --- |
| `cultivation-status` | 查看服务器转数、资质、经验、证明 |
| `cultivation-xp` | 模拟可信奖励，增加 100000 经验 |
| `cultivation-proof` | 凡人巅峰模拟本转试炼/升仙；六/七转每次模拟一次对应灾劫；八转每次模拟一次万劫、100000 道痕及两项成尊证明 |

控制台不远程暴露，KCP 战斗中也拒绝新增演示经验/凭据。六转以上需累计三次对应灾劫，不能一次凭据直接越级。

```powershell
./tools/Test-Foundation.ps1
./tools/Test-Architecture.ps1
./tools/Test-ClientDemo.ps1 -Mode All -Filter 'InsectSpace.' -TimeoutSeconds 300
# LocalCultivation 已处于 Play 后：
./tools/Test-CultivationDemo.ps1
```

最后的脚本在 17777–17780 端口启动**自己的**一次性服务器。开窍/突破均由 Unity 通过 TCP 发起；经验/证明通过该服务器明确的本地控制台提供。验收重复开窍拒绝、重连不重抽、全部突破门槛、一至九转及上限，钱包保持 (100,10)。结束时只关闭自己创建的进程并恢复客户端原端口，不停止其他服务；端口占用时拒绝运行，可通过参数选择其他四个端口。证据在 `.artifacts/validation/cultivation/`，实际结果见 [Validation](Validation.md)。
