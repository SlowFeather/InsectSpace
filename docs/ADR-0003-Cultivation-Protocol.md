# ADR-0003：转数与一次随机资质协议

日期：2026-10-02。状态：本地业务实现，公共契约提取/生产接入待平台与服务端评审。

## 决策

- 转数、资质、突破证明按服务端角色身份绑定。普通角色从未开窍开始，首次开窍在锁内抽样；同一进程中重复创建、并发请求、断线重连不重抽。
- 一至五转使用四小阶，六至九转使用 None；九转为上限。资质、流派境界、仙窍品级、钱包和能量余额分别建模。
- 普通池采用既有新手稿丁/丙/乙/甲 20/50/25/5 初测权重，不含十绝或无资质。随机只在服务端非战斗创建流程执行；共享规则使用纯整数映射。
- 只暴露快照、开窍、突破下一步三个命令；经验和证明来自可信服务端事件。事件去重、预期版本、整数边界和溢出校验防止重复晋升或客户端篡改。
- 新协议 PacketId 2003、WireVersion 1、RulesVersion 1；2001/2002 布局不变。本地 codec 分发复用同一连接，旧经济场景默认不订阅成长协议。
- KCP 房间活动期间拒绝成长修改。此次不重写旧资源样例的固定能量数值或技能规则。

## 迁移与回滚

协议暂归 `HotUpdate/Modules/Player/Cultivation/Protocol`，服务器编译链接源码，不依赖 Unity 或热更 DLL，不修改受保护目录/SDK。概率未来调整需规则版本与旧记录迁移，不能在登录时重新抽取。

当前无数据库迁移：内存进程退出即丢失。正式存储需稳定账号/角色槽、一次开窍约束、持久化幂等账本、奖励/挑战认证和审计。实际升仙关卡、机缘概率/保底、灾劫战斗、仙窍经营与资质改善并未由演示证明替代。

回滚可停用修炼场景/成长订阅，移除 2003 分发与 Compile Link，旧经济和 KCP 布局不变。公共契约提取或修改已发布资源协议仍需另行评审。

## 验证

验证全部 10000 个权重输入、边界、并发只抽一次、一至九转与全部九转门槛、事件/请求去重、跨角色隔离、溢出、畸形包、超时重试、真实 TCP 重连及 KCP 战斗期间拒绝突破。Unity 验证实际客户端模型/协议，UnityCLI 与独立服务器验证完整晋升链。结果见 [Validation](Validation.md)，字段、规则与来源见 [Cultivation](Cultivation.md)。
