# ADR 0004：凡蛊组合流派协议

状态：本地业务协议实现；生产接入仍需平台/服务端评审。2026-10-03。

在 Player 热更模块内新增无 Unity 依赖的凡蛊目录、整数判定及 2004/v1 协议，服务端以 Compile Link 编译同一份源文件。独立 Luban 配置位于 `design/luban/GuPaths`，独立 GuTables 管理器，不改动 AOT 启动表和受保护的 shared/vendor/Runtime/Editor。

客户端只提交最多六个已拥有蛊虫的定义 ID。当前背包是每种定义至多一只的最小所有权模型，同名不同转数不能重复装备。服务器绑定玩家/归属区，校验目录 SHA-256、规则版本、修订号、所有权、角色转数及战斗状态，再原子替换组合并返回评分。转数门槛是本项目初版规则，原作存在越阶使用，不把本规则当作原作设定。组合不自动赋予境界、道痕、技能伤害或炼蛊产物。

目录由 Luban 同步生成两端代码/数据，字节哈希作为兼容指纹。LOCAL 演示从专用 Resources 读取目录，服务端从输出 Data/GuPaths 读取同版本字节；生产资源接入应使用既有 YooAsset 服务，由业务注入字节，禁止失败后静默回退。

2001–2003 保持原格式。2004 有严格包长、数组、UTF-8 和 ID 上限。写操作保留有限幂等回执，达到上限拒绝而不逐出；重连/超时重试保留原操作内容。流派快照单独修订，角色转数每次请求读取修炼权威；主机单线程协调经济战斗、修炼和装备。

迁移/回滚：当前仅内存 LOCAL，重启丢失，无数据库迁移。目录或算法变更必须更新兼容标识；不兼容端拒绝装备写入。旧客户端可继续使用 2001–2003。生产上线需要身份认证、持久化和跨服务事务/战斗装备快照接入；本次不宣称完成这些能力。
